## ARC (added 2026-08-07) — async job pattern for slow work

- HQ-only, like Finn and Drip. Kenny's front office for raw sparks: video links (routed through `video-notes`), Substack articles, and social posts. Personality: film-room coordinator — quiet, precise, catalogs clean. Never drafts Kenny's actual piece for him; outline-building only, and only when he asks — his explicit line, 2026-08-07.
- Rooms: `MyKnowledgeOS/video-library/` (shared with the manual `/video-notes` skill) and `MyKnowledgeOS/idea-archive/` (his own — article/post capture notes). The runner's per-agent chat-log transcript is nested at `idea-archive/chat-log/`, NOT the room root — a scrimmage bug caught live: pointing an agent's `journal` config straight at a room it also writes curated files into clutters that room with daily transcript files.
- **Video transcription is async, not synchronous — this is the load-bearing design decision.** Local WhisperX (no GPU on this Mac) runs at ~0.65-0.75x realtime; measured live on Kenny's real 28-minute video: 18 minutes to transcribe, uncontended. That's far past what a single headless `claude -p` reply can hold open. ARC's allowlist deliberately does NOT include `video_notes.py`'s `process` subcommand — only `detect` (fast, routing) and `arc_tools/video_job.py` (`start`/`status`, also fast). `video_job.py start` pulls yt-dlp metadata, writes a job record to `~/.local/state/double-o-agents/arc/video-jobs/<job-id>.json`, and launches `video_notes.py process` DETACHED (`start_new_session=True`) so ARC's reply returns immediately with a real title/duration/estimate. A third daemon thread in `bot_runner.py`, `arc_video_loop` (60s poll, same pattern as `insight_loop`/`sched_loop`), watches for jobs whose PID has exited, then runs one more headless ARC call with the finished transcript and Kenny's original instructions attached — that call edits the note's analysis section and its reply gets pushed to Kenny via `deliver_unprompted`. A job that fails (no note produced, or the analysis call itself errors) still gets an honest push — never left silently unresolved.
- **A second bug the same scrimmage caught, fixed for every agent, not just ARC:** `run_claude`'s old `subprocess.run(..., timeout=...)` only killed the immediate child on timeout; `claude -p`'s Bash-spawned grandchildren (video_notes.py -> whisperx) were reparenting to init and continuing to run, unbounded, burning CPU and slowing every subsequent call. Fixed by launching with `start_new_session=True` and, on `TimeoutExpired`, `os.killpg(os.getpgid(proc.pid), signal.SIGKILL)` — the whole process group dies together now.
- Per-agent `timeout` override exists on `run_claude` (`agent_cfg.get("timeout", CLAUDE_TIMEOUT)`) but ARC does NOT use it — with the async split, his chat-turn calls are fast again; only `video_notes.py process` itself is slow, and it now runs entirely outside the timeout-bounded call.
- **Clipper power (granted 2026-08-09, /power-up):** ARC can cut interview clips by quote via the video-editor project's clipper skill (`MyCodeOS/video-editor/.claude/skills/clipper/clipper.py` — patched same day to anchor its dirs to its own project root instead of cwd, so headless runs land clips in the same `assets/clips/` library; clipper scrimmage re-passed 15/15 after the change). Same async split as video: fast subcommands `catalog`/`find` are allowlisted directly; slow `pull` (full source download + possible WhisperX) runs ONLY through `arc_tools/clip_job.py` (`start`/`status`, video_job.py's exact detached pattern, jobs in `~/.local/state/double-o-agents/arc/clip-jobs/`). `pull` and `verify` are deliberately NOT allowlisted synchronously. `arc_video_loop` polls both job dirs (shared `_poll_arc_jobs` helper); a finished clip job pushes clip path + matched transcript text (Kenny's review copy — he can't watch the clip) + match score, a not-found pushes the honest refusal with the matcher's best candidate, a crash pushes the diagnostic — nothing goes silent. Finish handler scrimmaged 8/8 with planted success/not-found/crash cases before the first live run.

## Architecture

- `bot_runner.py` — the whole runtime. One process; Claude Code CLI headless (`claude -p --safe-mode`) for the brain, Double-O HQ webchat as the only live transport (Telegram polling code still exists per-agent but every token_file is absent on purpose — see Known limits). Also runs the insight engine thread, the scheduler, the ARC video watcher, and (added 2026-08-08) a heartbeat thread the watchdog checks for liveness. Stdlib only, no pip.
- **Insight engine** (built 2026-07-26): on random days (P.A. ~30%, Marcus ~45%), at a random time between 10 AM and 9 PM, an agent re-reads its recent journal (14-day lookback) and texts Kenny ONE unprompted insight — or PASSes and stays silent. Max one per agent per day; the daily plan persists in state so restarts never re-roll. Sent insights are logged and fed back so they don't repeat. Manual test: `python3 bot_runner.py --insight marcus` (or `pa`).
- **Scheduled sends** (built 2026-07-26, later the same day): P.A.'s fixed-time plays, replacing the dead iMessage morning-brief pipeline. (1) **Morning Brief** every day at **2:30 AM** — built from real MyLifeOS files (goals, omg-kenny, Grantonomy, marketing ideas, MyCareerOS, wisdom pool) plus live Todoist, following the PRD at `MyProjectsOS/morning-brief/PRD-v0.md`. (2) **Safety rule** Mon–Thu at **4:30 AM** (before Kenny's ~4:40 work ride) from `MyProjectsOS/morning-brief/safety-pool/seed-pool.md`. Both land in P.A.'s history/journal so Kenny can talk back and fine-tune. Served quotes/rules are logged in `sched/` and fed back — no repeats within 30 days. One send per job per day (manual tests count); a send missed past its grace window (brief 9:00, safety 6:00) is skipped, never made up. After a workday brief, `caffeinate` holds the Mac awake until 4:50 for the safety send. Manual test: `python3 bot_runner.py --brief` (or `--safety`).
- `agents/<name>.md` — each agent's personality file, injected as the system prompt every call. Edit these in plain English to change behavior; no code changes needed.
- **Voice-journal pipeline** (built 2026-08-01): Kenny records in iPhone Voice Memos and saves the m4a into a subfolder of the iCloud shared folder `~/Library/Mobile Documents/com~apple~CloudDocs/journal-drop/` (subfolders: `business/ morning/ night/ love/ tarot/ post-ideas/`; the folder is shared cross-Apple-ID because the Mac and phone are on different iCloud accounts). `journal_watcher.py` — its own launchd job `com.kennethalford.journal-watcher` (WatchPaths + every 120s), NOT part of bot_runner — transcribes locally (`transcribe.py`: ffmpeg → WhisperX, no diarization), files the verbatim transcript through `pa_tools/journal.py` (audit-logged, append-only, no delete command exists), archives audio + transcript to `~/.local/state/double-o-agents/voice/archive/YYYY-MM/` (kept forever, ~1 MB/min, outside the repo), sends a P.A. confirmation text, quietly enriches frontmatter (mood/themes/energy — body is guarded byte-identical), and has Marcus text a reflection on the entry (the therapy loop; back-to-back memos get ONE combined reflection). Root-level drops route by spoken keyword, else to `JOURNALS/INBOX/` — nothing is lost. Failed transcriptions retry 3x then notify once; audio stays put. Crash mid-pipeline recovers from per-file sidecars in `voice/sidecars/`. Manual pass: `python3 journal_watcher.py --once`.
- **Journal review sends** (added 2026-08-01, in bot_runner's scheduler): `weekly-marcus` Sun 18:00 (patterns + 2-3 questions from Kenny's own entries), `weekly-pa` Sun 18:30 (business + post-idea review), `monthly-marcus` the 1st at 19:00 (30-day deep read; scheduler entries now support an optional `"dom"` day-of-month key). Each also writes a note into the vault: `JOURNALS/WEEKLY-INSIGHTS/` and `JOURNALS/MONTHLY-INSIGHTS/` (uppercase folder names deviate from the lowercase rule on purpose — they sit inside the vault's existing all-caps JOURNALS tree, 2026-08-01). Manual tests: `python3 bot_runner.py --weekly-marcus` / `--weekly-pa` / `--monthly-marcus`.
- Transport is deliberately thin so it can be swapped for Twilio/iMessage later without touching the brains.
- **Double-O HQ web chat** (built 2026-08-01 night): `webchat/server.py` — Kenny's accessible, VoiceOver-first front door, born of Telegram's broken VO scrolling. Stdlib HTTP server on port 8377, LAN-only, serving `webchat/static/` (plain HTML/JS, no build step). Threads: P.A., Marcus, and the Hollis + Nat huddle (same `duo-health` history key the Telegram group uses). Replies run through bot_runner's `load_persona`/`run_claude` and the SAME history + journal files, so web and Telegram are one continuous conversation per agent. `single_worker`/`duo_worker` in server.py deliberately mirror `ask_claude`/`duo_reply` instead of calling them — the user message must be saved before the reply cooks so the UI can render it, and bot_runner stays untouched. Auth: key at `~/.config/double-o-agents/webchat.key` (0600, auto-generated), sent as `X-Auth-Key`; the UI stores it in localStorage after Kenny opens the `#key=...` link once. Run detached with PID file `~/.local/state/double-o-agents/webchat.pid`, log `logs/webchat.log`: `nohup /usr/bin/python3 webchat/server.py >> ~/.local/state/double-o-agents/logs/webchat.log 2>&1 &`. Known v0 limits: no push notifications (unprompted sends still land on Telegram; they DO appear in HQ history), phone must be on home Wi-Fi, Mac must be awake, and simultaneous Telegram + web writes to one agent's history are last-write-wins. **Message queueing (added 2026-08-09):** sends that arrive while a reply is cooking are no longer 409-rejected (the UI dropped those silently — read as "agent not responding" to a VoiceOver user, twice in two days). do_POST now saves every message to history immediately and sets a `queued_more` flag; `single_worker`/`duo_worker` loop via `_trailing_user_block` until no unanswered user messages remain, answering everything that stacked up as one turn. Verified live with a two-message race test against Drip.
